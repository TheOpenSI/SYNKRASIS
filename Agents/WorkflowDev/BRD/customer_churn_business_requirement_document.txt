## **1. WHAT WE NEED**

We need an automated system that predicts which customers are likely to cancel their subscriptions, so our Customer Success team can intervene proactively. Currently, this is done manually by our data analyst once a week, and it's not scalable.

### **Current Situation:**
- Our data analyst spends 2 days per week pulling data from multiple systems, cleaning it, and running a model in Excel
- By the time we get predictions, they're already outdated
- We're missing opportunities to save at-risk customers
- Our churn rate is 18% annually, costing us approximately £2.3M in lost revenue

### **What We Want:**
- **Daily predictions** of which customers are at risk of churning
- A **list of high-risk customers** delivered to our Customer Success team each morning
- This should run **automatically** without manual intervention
- We want to **reduce churn by 10%** within 6 months (saving ~£1.2M annually)

### **Daily Schedule:**
- **Run Time:** 02:00 UTC every day (including weekends)
- **Must Complete By:** 07:45 UTC
- **Ideal Completion:** 06:00 UTC (gives 1h45m buffer)

- CRM database finishes nightly refresh at 01:30 UTC

### **Catch-up Behaviour:**
If the workflow fails:
- Retry automatically (at least 2 times with 15-minute gap between retries)

## **13. CURRENT MANUAL PROCESS (FOR CONTEXT)**

**What Emma Does Today (Every Monday):**

**08:00-09:00:** Pull customer data
- Logs into CRM database via pgAdmin
- Runs SQL query, exports to CSV
- ~75,000 rows

**09:00-10:00:** Pull usage data
- Connects to MySQL database
- Runs several queries for different metrics
- Exports to separate CSV files

**10:00-11:00:** Pull support data
- Logs into Zendesk web interface
- Manually exports ticket data
- Limited to 1,000 rows at a time, has to paginate

**11:00-13:00:** Clean and merge data
- Opens all CSV files in Excel
- Uses VLOOKUP to merge datasets on customer_id
- Manually fills missing values
- Calculates some metrics (e.g., login frequency = logins / days)

**13:00-14:00:** Run model
- Uses a logistic regression formula she built in Excel
- 15 variables: login_frequency, ticket_count, contract_value, etc.
- Calculates churn probability

**14:00-15:00:** Create and send report
- Sorts by probability score
- Flags top 500 as "high-risk"
- Adds customer names and account manager emails
- Saves as CSV
- Emails to Customer Success team

**Pain Points:**
- Takes 6-8 hours every Monday
- Lots of manual steps = prone to errors
- Only weekly frequency (not daily)
- Emma is single point of failure (if she's sick/on holiday, it doesn't happen)
- Model never gets updated with new patterns
