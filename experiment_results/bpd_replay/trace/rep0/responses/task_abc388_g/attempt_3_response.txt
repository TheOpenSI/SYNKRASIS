### Step-by-step reasoning
- We have N sorted mochi sizes A1 ≤ A2 ≤ ... ≤ AN. For a query [L, R], we can only use the subarray A[L..R].
- We want the maximum number K of disjoint kagamimochi pairs (i, j) with L ≤ i < j ≤ R and Ai * 2 ≤ Aj.
- A key observation (exchange/non-crossing argument) for sorted sequences: there exists an optimal matching of size K in which the K pairs are formed by pairing the K smallest elements of the subarray with the K largest elements of the subarray, in corresponding order:
  - Pairs: (A[L], A[R-K+1]), (A[L+1], A[R-K+2]), ..., (A[L+K-1], A[R]).
- Therefore, the maximum K is the largest integer such that, for all t = 0, 1, ..., K-1:
  - A[L + t] * 2 ≤ A[R - K + 1 + t].
- This yields a straightforward feasibility check for a fixed K. With this, we can determine the answer for a query by binary searching K in [0, floor((R-L+1)/2)] and testing the above inequality for all t in [0, K-1].
- While a direct O(length) per query approach (two-pointer greedy) also works, the binary-search-with-feasibility-check is clean and relies on the proved non-crossing matching structure. We optimize the feasibility check with early exits for speed (check endpoints first before iterating in the middle).

Time complexity per query:
- O(log M) feasibility checks, where M = floor((R-L+1)/2).
- Each feasibility check is O(K) in the worst case, but we exit early as soon as an inequality fails.
- While worst-case input could be heavy, this approach is correct, avoids the blossom-based complexity, and aligns with the problem’s non-crossing optimal matching property.

Space usage is O(1) extra per query beyond the input array.

import sys

def solve():
    data = sys.stdin.buffer.read().split()
    it = iter(data)

    N = int(next(it))
    A = [int(next(it)) for _ in range(N)]
    Q = int(next(it))

    out_lines = []
    for _ in range(Q):
        L = int(next(it)) - 1
        R = int(next(it)) - 1

        m = R - L + 1
        max_k = m // 2
        if max_k == 0:
            out_lines.append("0")
            continue

        # feasibility check: for a given K, check
        # for t in 0..K-1: A[L+t]*2 <= A[R-K+1+t]
        arr = A  # local alias for speed

        def feasible(K: int) -> bool:
            if K <= 0:
                return True
            # quick endpoints check to prune early
            if arr[L] * 2 > arr[R - K + 1]:
                return False
            if arr[L + K - 1] * 2 > arr[R]:
                return False
            # full check
            end_r = R - K + 1
            base_l = L
            for t in range(1, K - 0):  # we already checked t=0 above
                if arr[base_l + t] * 2 > arr[end_r + t]:
                    return False
            return True

        # Binary search for maximum K
        lo, hi = 0, max_k
        while lo < hi:
            mid = (lo + hi + 1) // 2
            if feasible(mid):
                lo = mid
            else:
                hi = mid - 1

        out_lines.append(str(lo))

    sys.stdout.write("\n".join(out_lines))

if __name__ == "__main__":
    solve()
