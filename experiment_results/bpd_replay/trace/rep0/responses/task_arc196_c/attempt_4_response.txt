### Step-by-step reasoning

- We have 2N vertices, with edges i -> i+1 for i = 1..2N-1, and we will add N edges from white vertices to black vertices by pairing each white with a black.
- The final graph must be strongly connected. A known approach to such problems is to look at the prefixes of the vertex sequence and count how many white/black pairs cross cuts between blocks of the sequence.
- A standard technique partitions the 2N vertices into blocks by scanning left to right and cutting at positions where the number of Ws equals the number of Bs in the prefix (diff becomes 0). Each block starts with a B and ends with a W (since the total counts in a block are equal and the first symbol in a block is B, the last must be W). Let a_t be the number of Ws in the t-th block. The total number of Ws is N, so sum_t a_t = N. Let L be the number of blocks.
- To obtain strong connectivity, every cut between consecutive blocks must be “crossed” by at least one added edge going from some white on the left side to some black on the right side. Counting pairings that fail to cross a given set of cuts and applying inclusion-exclusion leads to a combinatorial DP over the blocks.
- A commonly implemented DP uses:
  - pref[i] = sum of a_1 + a_2 + ... + a_i (the cumulative whites up to block i).
  - dp[i] is the total contribution for the first i blocks (with the alternating sign depending on how many segments we form).
  - A naive recurrence (which matches the inclusion-exclusion over consecutive block partitions) is:
    dp[i] = fact[pref[i]] - sum_{j=1}^{i-1} dp[j] * fact[pref[i] - pref[j]].
  - Finally the answer is dp[L].
- However, this recurrence is delicate: if you implement it directly, you must be careful with correctness on all inputs, and it can lead to wrong results on some cases if the underlying model of “cuts must be crossed” isn’t exactly as assumed.
- The previous solution attempted to accelerate the O(L^2) DP with a CDQ-based convolution, which is a valid speed-up technique for this particular structure. But the test for input 9 and the given string showed a mismatch: the computed value was 277752 whereas the correct answer is 240792. That indicates the used recurrence or the modeling of the cuts/segments is not aligning precisely with the problem’s correct combinatorial model for all inputs.

MOD = 998244353

def solve():
    input = sys.stdin.readline
    line = input().strip()
    while line == "":
        line = input().strip()
    N = int(line)
    S = input().strip()

    total_len = 2 * N
    if len(S) != total_len:
        print(0)
        return

    # Some necessary (but not always sufficient) conditions observed in problems like this
    # If the first vertex is white or the last vertex is black, strong connectivity is impossible.
    # The problem-specific necessary conditions observed in samples: S[0] must be 'B' and S[-1] must be 'W'
    if S[0] != 'B' or S[-1] != 'W':
        print(0)
        return

    # Build blocks: split when the prefix diff (#W - #B) returns to zero
    diff = 0
    curr_w = 0
    a = []
    for i in range(1, total_len + 1):
        ch = S[i - 1]
        if ch == 'W':
            diff += 1
            curr_w += 1
        else:
            diff -= 1
        if i != total_len and diff == 0:
            a.append(curr_w)
            curr_w = 0
    a.append(curr_w)

    L = len(a)
    # pref[i] = total whites in first i blocks
    pref = [0] * (L + 1)
    for i in range(1, L + 1):
        pref[i] = pref[i - 1] + a[i - 1]

    # Precompute factorials up to N
    fact = [1] * (N + 1)
    for i in range(1, N + 1):
        fact[i] = fact[i - 1] * i % MOD

    # If the number of blocks is small, use the straightforward O(L^2) DP
    NAIVE_LIMIT = 1000
    if L <= NAIVE_LIMIT:
