### Step-by-step reasoning
- Understand the two operations:
  - Swap adjacent elements anywhere. This operation can alter the sequence of colors and how many runs (consecutive equal values) exist.
  - Delete a prefix that is all the same value. This operation effectively deletes a prefix consisting of the first run (or a prefix of that run, but deleting more of the first run is always at least as good as deleting less).
- Key observation: Deleting a whole run from the front reduces the number of runs by exactly 1. Swaps can be used to merge two outer runs of the same color that are separated by a single run of arbitrary color, provided that the middle run has length 1. In such a configuration, a single swap reduces the total number of runs by 2 (three consecutive runs effectively collapse into a single run).
  - Pattern that enables a single beneficial swap: running indices i, i+1, i+2 such that:
    - colors[i] == colors[i+2]
    - lengths[i+1] == 1
  - After performing such a swap, the three runs collapse in a way that reduces the total number of runs by 2.
- Therefore, let M be the number of runs in A (after run-length encoding). If we can select k disjoint (non-overlapping) triples of consecutive runs satisfying the above pattern, we can perform k swaps that each reduce M by 2, and then delete the remaining M - 2k runs (one deletion per remaining front run). Total operations:
  - total_ops = k swaps + (M - 2k) deletions = M - k
- To maximize efficiency, we should maximize k, the number of non-overlapping valid triples. This is a classic 1D DP over the run list:
  - good(i) is true if i <= M-3, colors[i] == colors[i+2], and lengths[i+1] == 1.
  - dp[i] = maximum number of swaps we can perform starting from run i to the end.
  - Transitions:
    - Skip current i: dp[i] = dp[i+1]
    - Take the triple starting at i (if good(i)): dp[i] = max(dp[i], 1 + dp[i+3])
  - Base: dp[M] = dp[M+1] = dp[M+2] = 0
- Answer for a test case: M - dp[0].
- Complexity: Building runs is O(N). DP over M runs is O(M). Since sum N over test cases is at most 2e5, this runs efficiently.

Edge cases:
- If M < 3, there are no good triples; answer is M.
- The approach uses non-overlapping triples, which aligns with the fact that after performing a swap that collapses a triple, the involved runs are effectively merged and cannot participate in another overlapping triple.

import sys

def min_operations_for_case(N, A):
    # Build run-length encoding: colors and their run lengths
    colors = []
    lengths = []
    if N == 0:
        return 0
    cur = A[0]
    cnt = 1
    for x in A[1:]:
        if x == cur:
            cnt += 1
        else:
            colors.append(cur)
            lengths.append(cnt)
            cur = x
            cnt = 1
    colors.append(cur)
    lengths.append(cnt)

    M = len(colors)
    if M == 0:
        return 0

    # DP to maximize number of non-overlapping valid triples
    dp = [0] * (M + 4)  # extra space to avoid bounds
    for i in range(M - 1, -1, -1):
        best = dp[i + 1]  # skip starting at i
        if i <= M - 3 and colors[i] == colors[i + 2] and lengths[i + 1] == 1:
            val = 1 + dp[i + 3]
            if val > best:
                best = val
        dp[i] = best

    return M - dp[0]

def main():
    data = sys.stdin.buffer.read().split()
    t = int(data[0])
    idx = 1
    out_lines = []
    for _ in range(t):
        n = int(data[idx]); idx += 1
        A = list(map(int, data[idx:idx+n])); idx += n
        out_lines.append(str(min_operations_for_case(n, A)))
    print("\n".join(out_lines))

if __name__ == "__main__":
    main()
