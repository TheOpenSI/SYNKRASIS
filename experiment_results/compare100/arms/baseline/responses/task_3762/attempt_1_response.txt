### Step-by-step reasoning
- Let k_i be the number of times we visit index i after exactly m moves (excluding the starting position -1). Each visit to i yields points[i], so the final score at i is k_i * points[i].
- We want to maximize the minimum across all i: min_i (k_i * points[i]).
- If we target a candidate value S for this minimum, we need k_i such that k_i * points[i] >= S for every i. This implies k_i >= ceil(S / points[i]) for every i. Let t_i = ceil(S / points[i]).
- Any feasible solution with minimum at least S must have k_i >= t_i for all i. The total number of moves is m, so a necessary condition is sum_i t_i <= m.
- Is this condition also sufficient? Intuition and constructive argument:
  - If S > 0, we must visit every index at least once (otherwise its score would be 0 and thus the minimum would be 0). That requires at least n moves (starting from -1, first move to 0, then visit 1, ..., n-1).
  - If sum_i t_i <= m, we can realize at least t_i visits per index by combining a base pass that visits all indices once and then distributing the remaining visits via back-and-forth moves along adjacent indices. Each extra back-and-forth (a 2-move cycle on some adjacent pair) increases the counts of the two involved indices by 1 each. By using these cycles (and possibly an extra final move when needed), we can raise the counts to meet or exceed t_i for every i while keeping the total moves within m. Since we only require k_i to be at least t_i (not exactly), this is feasible.
  - Therefore, the feasibility test for S reduces to checking whether sum_i ceil(S / points[i]) <= m.
- Based on that, we can binary search S in [0, max(points) * m], because the largest possible score on any single index after m visits is bounded by visiting that index every move: score <= points[i] * m <= max(points) * m.
- Time complexity: Each feasibility check runs in O(n). Binary search over roughly up to log2(max(points) * m) iterations, which is at most around 50 for the given constraints. Overall O(n log(max(points) * m)) time and O(1) extra space.

- Edge cases:
  - If m < n, you cannot visit all indices even once, so the maximum minimum is 0. The check sum ceil(S / points[i]) <= m enforces this naturally.
  - Large m and large points are handled by Python integers without overflow.

### Code
```
from typing import List

class Solution:
    def maxScore(self, points: List[int], m: int) -> int:
        # Binary search on the maximum feasible minimum score S
        lo, hi = 0, max(points) * m

        while lo < hi:
            mid = (lo + hi + 1) // 2
            total = 0
            for p in points:
                # ceil(mid / p) = (mid + p - 1) // p
                total += (mid + p - 1) // p
                if total > m:
                    break  # early exit if already impossible

            if total <= m:
                lo = mid
            else:
                hi = mid - 1

        return lo
```
