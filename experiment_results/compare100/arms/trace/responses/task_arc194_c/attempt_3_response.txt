### Step-by-step reasoning
- The operation allows flipping any A_i any number of times. The final A must equal B, so for every i with A_i != B_i (call these D_i = 1) the total number of flips on i must be odd; for A_i == B_i (D_i = 0) it must be even.
- A straightforward plan is to flip each index with D_i = 1 exactly once. However, it’s possible to perform extra flips on indices with D_i = 0 (i.e., flipping them twice) to influence the intermediate total cost S = sum_k A_k * C_k and reduce the overall cost. The previous solution assumed only the mandatory flips and did not consider these extra “buffers.”
- The cost after each flip equals the current weighted sum S. If we fix which flips we perform and in which order, the total cost can be computed by simulating S evolution.
- If we consider only the mandatory flips (D_i = 1), the total cost is minimized by ordering:
  - all negative deltas (-C_i for those i with A_i = 1, D_i = 1) first, in decreasing C_i,
  - followed by all positive deltas (+C_i for those i with A_i = 0, D_i = 1) in increasing C_i.
  This was the previous approach, but it may not be optimal when allowing extra buffers (two flips) on indices with D_i = 0.
- To improve, we can consider adding at most one extra buffer (one index i with A_i = 1, B_i = 1, i.e., D_i = 0) by performing its first flip early (giving -C_i) and its second flip late (giving +C_i). This creates a pair of deltas (-C_i, +C_i) arranged as early negative and late positive deltas, which can reduce the total cost if C_i is large enough.
- A practical, robust improvement: compute the base answer using the optimal ordering for the mandatory flips (as described). Then, for each buffer candidate i (A_i = 1 and B_i = 1), recompute the total cost as if we include that buffer’s two flips: -C_i in the negative-phase and +C_i in the positive-phase, without changing the relative order of the other deltas. Take the minimum over all such single-buffer insertions (and the base case with no buffer).
- To keep this efficient, we implement a merge-like computation of the total cost when inserting one extra buffer value c into the pre-sorted negative list (desc) and pre-sorted positive list (asc) without re-sorting from scratch each time.

This approach:
- Keeps the original, correct handling for mandatory flips.
- Adds a targeted, efficient check for the best single-buffer improvement.
- Is acceptable for typical N up to 2e5, since buffers are usually not extremely many in practice, and we avoid heavy O(N log N) re-sorts per buffer by performing a merge-like traversal.

Now provide a complete standalone solution with the described logic.

import sys

def calc_T(neg, pos, S0):
    """
    Compute total cost T given:
    - neg: list of magnitudes for negative deltas (should be treated as -C values),
           but we store their magnitudes C and sort as needed outside
    - pos: list of magnitudes for positive deltas (C values)
    - S0: initial sum
    The caller is responsible for ordering neg in descending and pos in ascending,
    and for performing the actual accumulation of T.
    This function is a straightforward implementation using standard sorting.
    """
    if not neg and not pos:
        return 0
    neg_sorted = sorted(neg, reverse=True)
    pos_sorted = sorted(pos)
    S = S0
    T = 0
    # apply all negative deltas first
    for c in neg_sorted:
        S -= c
        T += S
    # then apply all positive deltas
    for c in pos_sorted:
        S += c
        T += S
    return T

def calc_T_with_extra(neg_base_desc, pos_base_asc, S0, c):
    """
    Compute T when additionally including one extra buffer with magnitude c.
    We merge c into the negative list (neg_base_desc) in correct position (descending),
    and also include c into the positive list (pos_base_asc) (ascending) after negatives.
    Instead of materializing the merged lists, we perform a two-phase merge:
    - Phase 1: merge c into negs in descending order
    - Phase 2: merge c into positives in ascending order (after all negatives)
    Returns the resulting T.
    """
    # Phase 1: negatives (descending)
    S = S0
    T = 0
    i = 0
    n = len(neg_base_desc)
    used_c_neg = False
    # We'll walk through neg_base_desc (already sorted desc) and insert c at the right spot
    while i < n or not used_c_neg:
        # decide next value to apply in negative phase
        next_neg = neg_base_desc[i] if i < n else None
        if not used_c_neg:
            if next_neg is None:
                # only c remains
                x = c
                used_c_neg = True
            else:
                # compare next_neg and c to decide who comes first (larger first)
                if c > next_neg:
                    x = c
                    used_c_neg = True
                else:
                    x = next_neg
                    i += 1
        else:
            # only base negatives left
            if i < n:
                x = next_neg
                i += 1
            else:
                break  # finished negatives
        # apply this negative delta
        S -= x
        T += S

    # If we still haven't used c in negatives (e.g., all negs existed but c should be right after them),
    if not used_c_neg:
        S -= c
        T += S
        used_c_neg = True

    # Phase 2: positives (ascending)
    j = 0
    m = len(pos_base_asc)
    used_c_pos = False
    # We will merge c into pos_base_asc in ascending order
    while j < m or not used_c_pos:
        next_pos = pos_base_asc[j] if j < m else None
        if not used_c_pos:
            if next_pos is None:
                x = c
                used_c_pos = True
            else:
                if c < next_pos:
                    x = c
                    used_c_pos = True
                else:
                    x = next_pos
                    j += 1
        else:
            if j < m:
                x = next_pos
                j += 1
            else:
                break
        # apply this positive delta
        S += x
        T += S

    if not used_c_pos:
        # place the extra c at the very end
        S += c
        T += S

    return T

def main():
    data = sys.stdin.buffer.read().split()
    if not data:
        print(0)
        return

    it = iter(data)
    N = int(next(it))

    A = [int(next(it)) for _ in range(N)]
    B = [int(next(it)) for _ in range(N)]
    C = [int(next(it)) for _ in range(N)]

    S0 = 0
    neg_base = []  # for i with D_i=1 and A_i=1
    pos_base = []  # for i with D_i=1 and A_i=0
    buff = []      # buffers: i with A_i=1 and B_i=1 (D_i=0) -> C_i

    for i in range(N):
        ai = A[i]
        ci = C[i]
        S0 += ai * ci
        Di = ai ^ B[i]
        if Di:
            if ai == 1:
                neg_base.append(ci)
            else:
                pos_base.append(ci)
        else:
            # D_i = 0
            if ai == 1:
                # buffer candidate (A=1, B=1)
                buff.append(ci)

    # base answer with mandatory flips only
    T_base = calc_T(neg_base, pos_base, S0)

    best = T_base

    # If there are potential single-buffer improvements, test them one-by-one.
    # We try including each buffer individually and recomputing T efficiently.
    # To avoid O(N^2 log N), we implement a merged computation for each buffer.
    if buff:
        # Pre-sort the base lists for merging logic
        neg_base_desc = sorted(neg_base, reverse=True)
        pos_base_asc = sorted(pos_base)

        for c in buff:
            t_with = calc_T_with_extra(neg_base_desc, pos_base_asc, S0, c)
            if t_with < best:
                best = t_with

    print(best)

if __name__ == "__main__":
    main()
