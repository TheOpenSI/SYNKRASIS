### Step-by-step reasoning
- We need, for each query (R, X), the length of the longest strictly increasing subsequence (LIS) within the prefix A[1..R] using only elements A[i] <= X.
- A direct per-query LIS is too slow. We can process offline by sorting by value A[i], grouping equal values together.
- For a fixed value v, consider all indices i with A[i] = v. Any LIS ending at i can only use previous elements with value < v. If we maintain a Fenwick tree F over indices 1..N that stores the best LIS length ending at index j for all processed (smaller) values, then for i in the group with value v:
  - L[i] = 1 + max LIS length among j < i with A[j] < v, which is F.query(i-1).
- We must not allow elements of the same value v to extend each other. So for a value group, first compute L[i] for all i in the group using the current F (which contains only smaller values). Then after computing all L[i] in the group, we update F for all i in the group with their L[i].
- To answer a query (R, X), we need the LIS length in the prefix R considering only values <= X. If we process values in increasing order and progressively update another Fenwick tree G that stores L[i] at index i once i’s value has been processed, then for a given X, the answer for R is max over i <= R of L[i] among all i with A[i] <= X. This is exactly G.query(R).
- Algorithm outline:
  - Build groups of indices by value: for each distinct value v, store all indices i with A[i] = v.
  - Sort distinct values ascending. Maintain Fenwick F for DP by index and Fenwick G for answers by prefix.
  - Read all queries, sort by X ascending. Process values in increasing order, and for each value v <= current query X:
    - For all i in the group of v, compute L[i] = 1 + F.query(i-1) (uses only smaller values).
    - After computing all L[i] for the group, update F at each i with L[i], and update G at i with L[i].
  - Answer for a query (R, X) is G.query(R).
- This runs in O((N + Q) log N) time and O(N) memory.

Edge cases:
- If multiple queries share the same X, they reuse the same processed groups.
- A[i] can be up to 1e9; we group by actual A values, not by coordinates.
- R can be as large as N; Fenwick supports that.

import sys

class FenwickMax:
    __slots__ = ('n', 'bit')
    def __init__(self, n):
        self.n = n
        self.bit = [0] * (n + 1)

    def update(self, i, val):
        bit = self.bit
        n = self.n
        while i <= n:
            if val > bit[i]:
                bit[i] = val
            i += i & -i

    def query(self, i):
        res = 0
        bit = self.bit
        while i > 0:
            if bit[i] > res:
                res = bit[i]
            i -= i & -i
        return res

def main():
    data = list(map(int, sys.stdin.buffer.read().split()))
    it = iter(data)
    N = next(it)
    Q = next(it)

    A = [0] * (N + 1)
    for i in range(1, N + 1):
        A[i] = next(it)

    # Group indices by value
    from collections import defaultdict
    groups = defaultdict(list)
    for i in range(1, N + 1):
        groups[A[i]].append(i)

    # Sorted distinct values
    values = sorted(groups.keys())

    # Read queries
    queries = []
    for qi in range(Q):
        R = next(it)
        X = next(it)
        queries.append((X, R, qi))

    # Sort queries by X ascending
    queries.sort()

    # Fenwick trees
    F = FenwickMax(N)  # DP by index, for previously processed (smaller) values
    G = FenwickMax(N)  # Answer DP by prefix: stores L[i] for processed indices

    # Temporary storage for L[i] during a value group
    Ltmp = [0] * (N + 1)

    ans = [0] * Q
    p = 0  # pointer into values
    total_values = len(values)

    for X, R, qi in queries:
        # Process all value groups with v <= X
        while p < total_values and values[p] <= X:
            v = values[p]
            idxs = groups[v]
            # Compute L[i] for all i in this group using current F (only smaller values)
            for i in idxs:
                # L[i] = 1 + max LIS ending before i with A[j] < v
                Ltmp[i] = 1 + F.query(i - 1)
            # Now update F and G for all i in this group
            for i in idxs:
                li = Ltmp[i]
                F.update(i, li)
                G.update(i, li)
                Ltmp[i] = 0  # reset for safety
            p += 1

        # Answer for this query: max L[i] with i <= R and A[i] <= X
        ans[qi] = G.query(R)

    # Output in original order
    out = '\n'.join(str(ans[i]) for i in range(Q))
    print(out)

if __name__ == "__main__":
    main()
